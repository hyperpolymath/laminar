== Project Architecture

=== Module Overview

The project follows a well-structured Elixir/Phoenix architecture:

[source]
----
apps/laminar_web/lib/
+-- laminar/
|   +-- block_transfer.ex          # Block-level transfer handling
|   +-- cli.ex                     # Command-line interface
|   +-- credential_pool.ex         # Multi-SA quota management
|   +-- filesystem_optimizer.ex    # Filesystem optimization
|   +-- filter_engine.ex           # File filtering rules
|   +-- ghost_linker.ex            # URL stub creation for large files
|   +-- intelligence.ex            # File routing decision engine
|   +-- live_transfer.ex           # Real-time WebSocket transfers
|   +-- network_tuning.ex          # Network optimization
|   +-- parallel_transfer.ex       # TOC-optimized transfer coordinator
|   +-- pipeline.ex                # Broadway 4-lane processor
|   +-- preflight.ex               # Pre-transfer validation
|   +-- rclone_client.ex           # Rclone RC API client
|   +-- refinery.ex                # File format conversion
|   +-- report_submitter.ex        # Feedback submission
|   +-- special_files.ex           # Special file handling
|   +-- transfer_metrics.ex        # Real-time performance metrics
+-- laminar_web/
    +-- application.ex             # OTP Application
    +-- endpoint.ex                # Phoenix Endpoint
    +-- router.ex                  # HTTP Routes
    +-- schema.ex                  # GraphQL Schema (Absinthe)
    +-- controllers/               # REST Controllers
    +-- channels/                  # WebSocket Channels
    +-- resolvers/                 # GraphQL Resolvers
----

=== Key Components

==== Control Plane (Elixir/Phoenix)

* *GraphQL API*: Absinthe-based API for transfer operations
* *CLI Interface*: Command-line management (`laminar credentials`, `laminar parallel`, etc.)
* *Intelligence Engine*: Smart file routing based on size, type, and content
* *Broadway Pipeline*: 4-lane processing (ghost/express/squeeze/refine)
* *CredentialPool*: Multi-service-account quota management

==== Data Plane (Rclone)

* *RC API*: HTTP JSON-RPC interface to rclone
* *40+ cloud providers*: S3, GDrive, Dropbox, OneDrive, B2, etc.
* *Multi-thread streams*: 8 parallel streams per large file

== Identified Issues

=== Critical Issues

[#issue-1]
==== CRIT-001: Missing Function Implementations in Pipeline

*Location*: `apps/laminar_web/lib/laminar/pipeline.ex`

*Description*: Tests reference functions that are not implemented in the Pipeline module:

[source,elixir]
----
# Expected by tests but not implemented:
Pipeline.new_job/2
Pipeline.update_status/2
Pipeline.assign_lanes/1
Pipeline.calculate_progress/1
Pipeline.calculate_batch_size/2
Pipeline.backoff_delay/1
Pipeline.should_retry/2
----

*Impact*: Test suite will fail with `UndefinedFunctionError`

*Recommendation*: Implement the missing functions or update tests to match actual API

[#issue-2]
==== CRIT-002: GraphQL Schema Type Error

*Location*: `apps/laminar_web/lib/laminar_web/schema/types.ex`

*Description*: The custom scalar `file_size` uses incorrect Absinthe 1.7+ syntax:

[source,elixir]
----
# Current (incorrect):
parse fn
  %{value: value}, _ when is_binary(value) -> {:ok, value}
  _, _ -> :error
end

# Should be (Absinthe 1.7+):
parse fn
  %Absinthe.Blueprint.Input.String{value: value} -> {:ok, value}
  _ -> :error
end
----

*Impact*: GraphQL queries with FileSize type will fail

*Recommendation*: Update to Absinthe 1.7+ syntax

[#issue-3]
==== CRIT-003: Missing RcloneClient Functions

*Location*: `apps/laminar_web/lib/laminar/rclone_client.ex`

*Description*: Tests expect functions not present in implementation:

[source,elixir]
----
# Expected by tests but not found:
RcloneClient.list_remotes/0
RcloneClient.list/2
RcloneClient.version/0
RcloneClient.rclone_url/0
RcloneClient.sync/3
RcloneClient.job_list/0
RcloneClient.job_stop/1
----

*Impact*: Integration tests will fail

*Recommendation*: Implement missing RC API wrappers

=== Medium Issues

[#issue-4]
==== MED-001: Missing Module Dependencies

*Location*: `apps/laminar_web/lib/laminar/transfer_metrics.ex`

*Description*: The module references undefined submodules:

[source,elixir]
----
alias Laminar.TransferMetrics.{
  ThroughputTracker,    # Not defined
  LatencyMonitor,       # Not defined
  OptimizationEngine,   # Defined inline
  NetworkProfile        # Defined inline
}
----

*Impact*: Compilation warning, potential runtime errors

*Recommendation*: Remove unused aliases or implement missing submodules

[#issue-5]
==== MED-002: Inconsistent Error Handling in CredentialPool

*Location*: `apps/laminar_web/lib/laminar/credential_pool.ex`

*Description*: Some functions return `{:ok, _}` / `{:error, _}` while others use atoms or raise exceptions inconsistently.

*Impact*: Unpredictable error handling in calling code

*Recommendation*: Standardize on `{:ok, result} | {:error, reason}` pattern

[#issue-6]
==== MED-003: Missing Application Supervision

*Location*: `apps/laminar_web/lib/laminar_web/application.ex`

*Description*: Several GenServers should be added to the supervision tree:

* `Laminar.CredentialPool`
* `Laminar.ParallelTransfer`
* `Laminar.TransferMetrics`
* `Laminar.LiveTransfer`
* `Laminar.ReportSubmitter`

*Impact*: Services may not start automatically or restart on failure

*Recommendation*: Add to Application supervision tree with appropriate restart strategies

[#issue-7]
==== MED-004: FilterEngine Reference Not Found

*Location*: `apps/laminar_web/lib/laminar/live_transfer.ex`

*Description*: References `FilterEngine.new/1` and `FilterEngine.to_rclone_args/1` but `filter_engine.ex` may not implement these.

*Impact*: Live transfers with filters will fail

*Recommendation*: Verify FilterEngine implementation matches usage

[#issue-8]
==== MED-005: TransferChannel Reference Without Implementation Check

*Location*: `apps/laminar_web/lib/laminar/live_transfer.ex`

*Description*: Calls `TransferChannel.broadcast_progress/2` etc. without checking if channel is connected.

*Impact*: Potential crashes when no WebSocket clients connected

*Recommendation*: Add guards or use Phoenix.PubSub directly with safe broadcasting

=== Low Priority Issues

[#issue-9]
==== LOW-001: Missing Typespec Annotations

*Impact*: Reduced Dialyzer effectiveness, harder documentation

[#issue-10]

*Location*: Multiple files

*Description*: Values like buffer sizes, timeouts, and endpoints are hardcoded:

*Recommendation*: Move to Application config for flexibility

[#issue-11]
==== LOW-003: Sample Data Structure Error

*Location*: `apps/laminar_web/lib/laminar/transfer_metrics.ex`

*Description*: Line 208 creates malformed sample:

[source,elixir]
----
# Current:
samples = [{sample} | Enum.take(transfer.samples, @rolling_window_size - 1)]

# Should be:
samples = [sample | Enum.take(transfer.samples, @rolling_window_size - 1)]

*Impact*: Metrics calculation errors

*Recommendation*: Remove extra tuple wrapping

[#issue-12]
==== LOW-004: DateTime to Date Conversion Issue

*Location*: `apps/laminar_web/lib/laminar/credential_pool.ex`

*Description*: `next_midnight_pacific/0` may have timezone calculation issues with DST

*Impact*: Incorrect quota reset timing during DST transitions

*Recommendation*: Use proper timezone library (Tzdata + Calendar)

== Conclusion

The Laminar project demonstrates solid architectural design with a well-thought-out approach to cloud-to-cloud transfers. The codebase follows Elixir/Phoenix conventions and includes sophisticated features like:

* Theory of Constraints optimization
* Multi-service-account quota management
* 4-lane Broadway pipeline for different file types
* Real-time WebSocket progress streaming

However, several implementation gaps exist between the test expectations and actual code. Addressing the critical issues identified in this report will enable the test suite to run successfully and improve overall code quality.

The project would benefit from:

. Completing the missing function implementations
. Adding unit tests for untested modules
. Implementing proper supervision tree
. Adding integration tests with mock rclone server
